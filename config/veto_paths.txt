# veto_paths.txt — verifier and engine paths (v3.1, maximum autonomy).
#
# Changes here merge automatically after the veto window
# (config/limits.yaml -> autonomy.veto_window_hours) unless Fahmi labels
# the PR `veto`. No approval is requested; the digest lists them.
#
# What stays HARD even inside these paths (scripts/autonomy_gate.py):
#   * removing or editing an existing case in scripts/eval_routing.json
#   * removing a test_* function from scripts/test_canary.py
#   * editing or deleting a known-bad sample in tests/bad/
#   * deleting any verifier, engine, or test file
# Adding cases and adding canaries are VETO; fixing engine code is AUTO.
# CI runs scripts/verifier_selftest.py on every change, so a
# patch that makes a check stop catching known-bad input turns red and
# never merges.
